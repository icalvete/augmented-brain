Commands

Every command of the program, with every option. Day to day you do not need them: you talk to Claude. They are for setting up, checking and moving to a new machine.

Run them in a terminal. Most act on the space of the folder you are in. Outside every space's folder, they use the default space.

cd ~/augmented-brain/work
augmented-brain check

Options go before or after the other arguments, with one dash or two (--all or -all). A command that gets an argument it does not take says so, and does nothing.

Three commands are started by Claude Code, not by you: mcp, hook and panel serve. They are here so you know what they are.

Inside Claude Code there is one slash command: /brain:panel opens the panel, as augmented-brain panel does.

augmented-brain init

Sets everything up: the spaces, the configuration and the Claude Code plugin. The installer runs it for you the first time.

augmented-brain init

With no options it asks nothing. It takes the language from the system and creates two spaces in ~/augmented-brain: work and personal (trabajo and personal in Spanish), with personal as the default space. Then it installs the plugin. Without Claude Code, it prints the two commands that install the plugin later.

If there is a configuration already, it stops and changes nothing. To add a space, use space add. It writes the configuration last: if it stops half way, run it again.

  • --custom: ask for the language, the space and its folders, to make one space your way.
  • --language: the language, en or es. Without it, the system's (or AB_LANGUAGE).
  • --space: the name of the one space to create (lowercase letters, digits and dashes, starting with a letter).
  • --work: its work folder. Default: ~/augmented-brain/<space>.
  • --memory: its notes folder. Default: notes inside the work folder.
  • --yes: do not ask; take the options given and the defaults.
  • --no-plugin: do not install the Claude Code plugin.

--space, --work or --memory make a single space instead of the two.

augmented-brain init --space client --work ~/clients/acme --language en

augmented-brain space

Says which space this folder belongs to, and where its notes are.

augmented-brain space

Outside every space's folder it names the default space. With no default space, it says so, and lists the spaces. It takes no options.

augmented-brain space add

Adds another space: a client, a side project, a volunteer job.

augmented-brain space add client

The name goes as an argument (first or last) or with --space. It asks for the work folder and the notes folder, suggesting ~/augmented-brain/<name> and its notes folder. If there was no default space yet, it sets one: personal if a space has that name, or else the space that was there first.

  • --space: the name of the new space.
  • --work: its work folder.
  • --memory: its notes folder.
  • --yes: do not ask; take the options given and the defaults.

It has no --language. The language is the same for every space on this computer: the language setting, which init sets. See Configuration.

augmented-brain space add client --work ~/clients/acme --yes

See Spaces.

augmented-brain check

Checks the notes of this folder's space, and rebuilds its index when they are all valid.

augmented-brain check

It also:

  • moves the notes to a new format when a new version needs it, after a full copy;
  • checks the shared notes, and rebuilds their index;
  • names every file that holds a secret (the backup refuses it until the secret is out);
  • names the repositories notes point at that are not on this computer;
  • makes the notes readable by you only, if other users could read them;
  • moves the list of secret names into secrets.toml, from config.toml where 0.6.0 kept it;
  • moves the oldest journal entries of a task past 24 KB to archive/journals/, as the tools do when they write it (see A long journal).

Run it after editing notes by hand. It ends with an error when a note is not valid. It takes no options.

augmented-brain doctor

Says what is missing, and how to fix it.

augmented-brain doctor

Each line starts with a mark: ✓ fine, · for your information, ! a warning, ✗ something that fails. Under a line that needs work, → says what to do. It checks:

  • the configuration, the profile and which space this folder is in;
  • each space's notes folder, its notes and its index, and whether it has a backup;
  • tasks too long to read in one go, which check shortens;
  • how much of every session start your rules take, with the three longest: they go whole to every session, so a shorter rule costs less each time;
  • Claude Code, git and the plugin, and whether Claude Code is recent enough to stop everything when the guard fails (2.1.295 or later);
  • the guard, for real, with a command that must be stopped;
  • the guard's lists, the root exceptions in root_ask, and those that have ended;
  • Claude sessions still running an older version after an update;
  • a second memory that Claude Code keeps of its own for your folders;
  • notes that other users of the computer could read;
  • whether there is a default space, and whether a restore left the guard's lists empty;
  • remote access, one line per space, when you set it up with remote install: a warning when its service is not running, Claude does not trust its folder yet, or (on Linux) linger is off;
  • how many versions of the configuration are kept, and whether it changed outside them (by hand);
  • the guard's lists changed since you last accepted them, and a repository both untouchable and allowed;
  • a Claude window using a lot of memory (2 GB or more);
  • the panel from another device, once you have used it: Tailscale, HTTPS, and an address left published;
  • what working with Claude Code left behind: its worktrees whose session is over, and the scratch folders of sessions that ended (see clean);
  • background sessions that keep their process while nobody uses them: ended or archived, or opened by no task and idle for over 12 hours (archiving one in Claude Desktop does not stop it), each with the claude stop that ends it.

It ends with an error when something fails. When the configuration cannot be read, it points to config history and config restore. It takes no options. See Troubleshooting.

augmented-brain import

Brings in a memory Claude Code already wrote. Without --apply it only shows what it would do.

augmented-brain import ~/.claude/projects/<folder>/memory
  • --apply: write the notes. Without it, nothing is written.
  • --map: a file that says which space each area or note goes to: lines area-x = space, task-y = space, lesson-z = shared, and * = space for the rest.
  • --repos-base: the folder the repos: paths of the source are relative to.

It never writes over a note that exists, and only reads the source. See Bring in a memory.

augmented-brain backup

Saves the latest changes of this folder's space to its private repository. It also runs by itself when a Claude session ends.

augmented-brain backup
  • --all: back up every space, not only this folder's.
  • --space: back up this space, wherever you are: --space work.
  • --auto: how the end of a session starts it, in the background. Quiet, and it never waits for a password. You do not need it.

It stops without pushing when a note holds a secret, or when another machine changed the same note in another way, and says which. See Backup and restore.

augmented-brain backup setup

Connects this folder's space to a private git repository. It does not copy anything yet: run augmented-brain backup afterwards for the first copy (it says so).

augmented-brain backup setup git@gitlab.com:lucia/brain-work.git

It takes one argument, the repository's address, and no options. To create the repository in your GitHub account for you, ask Claude: “set up the backup”.

augmented-brain restore

Brings a space back from its backup, on a new machine.

augmented-brain restore https://github.com/lucia/augmented-brain-work.git

It replaces the empty space of the same name with yours. It leaves alone a space that already has notes. It installs the Claude Code plugin if it is missing. Then it names what it did not bring: the guard's lists, the repositories where Claude may commit, and the secrets this machine's keychain lacks, each with the command to store it. When it cannot ask the keychain (there is none, or it is locked), it names the secrets it could not check.

  • --memory: where to put the space's notes. Default: where they were, inside the work folder.
  • --work: the work folder that selects the space. Default: the one saved in the backup.

augmented-brain panel

Opens the panel in your browser: today at a glance, and every page of your spaces to see and edit.

augmented-brain panel

It starts the panel in the background, or finds the one running, and opens the browser on Today, with the space of this folder. It returns at once. The panel stops by itself after 30 minutes without use. The address it prints opens the panel once, within 2 minutes; run by Claude, with the browser open, it prints none.

  • --no-browser: only print the address, do not open the browser. AB_NO_BROWSER=1 does the same.

See The panel.

augmented-brain panel remote

Opens the panel for your other devices (another computer, your phone), through Tailscale, a free app that joins your devices in a private network of their own.

augmented-brain panel remote

It starts the panel and publishes it in your Tailscale network only. If the panel is already open, that same panel answers through the network too, so the pages you have open keep working. It prints the address and a QR code to open it from the phone. Only your own devices, signed in with the account this computer belongs to, can open it; the address opens it once, within 10 minutes, and the pages stop working when the panel stops. Whatever is missing (Tailscale itself, HTTPS in your network, letting your user publish) it explains, with the step to take: it never installs or changes anything of Tailscale's for you. See The panel from another device.

augmented-brain panel stop

Stops the panel now.

augmented-brain panel stop

It says whether a panel was running. The link at the bottom of every panel page does the same.

augmented-brain panel serve

The panel itself, running in the background. augmented-brain panel starts it; you never run it by hand. It stops on its own after 30 minutes without use.

augmented-brain remote

Keeps Claude reachable from another computer or your phone, also after a reboot. It is three commands, install, uninstall and status, each with its own section below. It uses a systemd user service on Linux, a LaunchAgent on macOS and a task of the Task Scheduler on Windows. On Linux a fourth one, watch, is run by a timer, not by you. Without a subcommand, or with another, remote prints its usage. See Remote access.

augmented-brain remote install

Sets remote access up, one service per space.

augmented-brain remote install

For each space named in remote.toml (by default, the default space) it writes a service that runs claude remote-control in the space's first work folder (or the one folders names in remote.toml), and starts it: a systemd user service on Linux, a LaunchAgent in ~/Library/LaunchAgents on macOS, a task \augmented-brain\remote-<space> of the Task Scheduler on Windows (it runs while you are logged in, with no window). Only a space with no work folder gets a folder of its own, remote/<space> in the configuration folder, which becomes its work folder. It needs claude (on your PATH, or where its installer puts it) and a folder that exists. The service gets a PATH with the folders of claude and augmented-brain, so its sessions find both after a reboot. You can run it again at any time: it changes only what is different.

On Linux it also installs the watch: a systemd timer, augmented-brain-watch-remote, that runs augmented-brain remote watch every two minutes (see below).

It then says what is still missing, and does none of it for you:

  • Claude must trust each folder. It prints cd <folder> && claude for each one that is not trusted yet (on Windows, cd "<folder>"; claude): run it once and accept the question.
  • On Linux, linger must be on for the services to start after a reboot with nobody logged in. It prints the command, sudo loginctl enable-linger <you>, for you to run. macOS and Windows have no linger: the service starts when you log in.

Without systemd's user services (a container, or WSL without systemd), launchctl on macOS or the Task Scheduler on Windows, it says so and changes nothing. It takes no options. The settings are in remote.toml (see Configuration).

augmented-brain remote uninstall

Stops remote access and removes it.

augmented-brain remote uninstall

It stops and removes the services remote install wrote (on Linux, the watch first), and sets enabled = false in remote.toml. The folders and their entries in work_folders stay: it never deletes anything else. It takes no options.

augmented-brain remote status

Says how remote access stands, and changes nothing.

augmented-brain remote status

For each space: the session's name (what you pick in Claude Desktop or claude.ai), whether the service is running and starts by itself, and whether Claude trusts its folder. Then, on Linux, whether the watch (see remote watch below) is running and how long ago it last looked, and whether linger is on; on macOS and Windows, that it starts when you log in. Under each problem, → says what to do. It takes no options.

augmented-brain remote watch

Brings a service back when the server archived its session. Linux only. Its timer runs it every two minutes; you do not need to.

augmented-brain remote watch

A healthy claude remote-control keeps a Claude process for its session. When the server archives the session (for example, you archived it in claude.ai), that process ends and the service goes on running with no session: nobody can connect, and systemd sees nothing wrong. The watch notices a service with no session at two looks in a row and restarts it. If it still has none after that, Claude was trying to reopen the archived session: the watch renames Claude's record of it (bridge-pointer.json becomes bridge-pointer.json.archived, in the folder's project in ~/.claude/projects) and restarts it again, so a new session starts: about ten minutes in all. The conversation of the archived session does not come back. What it does goes to the system journal (journalctl --user -u augmented-brain-watch-remote). It takes no options.

On every look it also keeps your task sessions safe. Stopping a service stops everything started inside it, and a session of a task started from a remote session (with augmented-brain session start, or claude --bg) can start Claude's background service there, which runs every task session. So the watch moves out of each service whatever its server did not start itself (Claude's background service, its sessions, anything else a session left running) into a group of its own, augmented-brain-kept-<number>. remote install and remote uninstall do the same before they restart or stop a service; when it cannot be done, they stop and say so, and the watch does not restart that service.

augmented-brain session

Opens a remote session of its own for one task, so that from another computer you can work on several tasks at once, each in its own session. It is four commands, start, stop, restart and list, each with its own section below; restart also restarts the other Claude sessions on this computer. start, stop and list are Linux only for now: they have been tried only there; restart also works on macOS. Without a subcommand, or with another, session prints its usage. See A session per task.

augmented-brain session start

Opens a session for a task, in the task's folder.

augmented-brain session start task-new-website
augmented-brain session start task-new-website --folder ~/projects/website

It starts a background Claude session of its own for the task (claude --bg --remote-control), named after the task's title. Within a minute it shows up in Claude Desktop and claude.ai. It starts on its own: its first message has it read its task, tell you where it stands, and get on with the next step. When another Claude session asked for it, the first message also has it tell that session, in one line, when it stops: the task closed or parked, or waiting on you. Since you see what a background session writes only when you open it, it also sends you a notification then (on the desktop and, with Remote Control, on your phone), and when something it watched ends. The folder is the first of the task's repositories found in the space's work folders, or the one --folder gives. A task that names no repository opens in the space's first work folder, which several such tasks may share.

A bare repository has no files to work on, so the task gets a git worktree of its own next to it: site-new-website for the task task-new-website of site, on a new branch named after the task, from the default branch of origin as it is now (it fetches first). Two tasks of one repository never share a folder, and a session never starts on old code. Asked again, it uses the same worktree. The same goes for a bare repository given with --folder. A folder given with --folder must lie inside the work folders of the task's space: a session elsewhere would not find its task. On a system where task sessions do not run yet, the command says so before it makes anything.

Run it from a folder of the task's space: the remote session you reach from another computer can run it for you (“open me a session for the website task”). Every session on Linux knows how.

Two rules keep it safe. The folder must be trusted on its own: trusting a folder above it is not enough, so the first time the command says to open Claude once in that folder and accept the question. Claude itself would not ask, and a repository's own settings and hooks must not run unasked. A git worktree is the exception: Claude keeps the answer under its main repository, so trusting either one is enough. And one task per folder: two tasks in one folder would step on each other's changes, so a folder another task's session uses is refused; give it another with --folder (a git worktree, for example).

It waits for the session's first answer, up to a minute, and returns as soon as it comes. A session that cannot work is not left behind: when Claude Code is not logged in, or its login has expired, nothing is opened, and when the first answer is an error (the login ran out, the service is overloaded), the session is closed. Either way the command says what happened and what to do, such as logging in again with claude auth login.

If Claude stopped the task's session (it does that to one left unused for hours, and to every one when its background service restarts), session start brings it back instead: the same session, with its whole conversation, connected again in Claude Desktop and claude.ai, and no new first message. claude.ai shows such a session as disconnected and cannot bring it back by itself. Only if Claude refuses does a new session open and replace it.

The session closes with session stop, or when the computer restarts. Launched sessions are not brought back after a reboot: ask for them again.

augmented-brain session stop

Closes a task's session and takes it out of Claude Desktop and claude.ai. It works from any folder.

augmented-brain session stop task-new-website

When session start made a worktree for the task, stop also removes it with its branch, as long as nothing would be lost: with changes not committed (files git does not show by your settings count too), commits not pushed (on the task's branch, even when the worktree was left on another commit), or files git ignores that no build makes again (a .env, a key; node_modules, build, dist and the like do not count), it keeps it and says so. Closing the task closes its session too, once it has finished its answer, worktree and all. Sessions that end without stop (a reboot, a session closed from Claude Desktop) leave theirs: the next session start removes those with nothing of their own (not one made in the last ten minutes, whose session may still be starting), closing the task removes its own, and doctor only looks: it says how many would go and warns about any that stays with work in it.

If Claude cannot tell whether the session still runs (its list cannot be read), stop says so and changes nothing: the session stays on record and its worktree stays too.

A session Claude retired (it does that to one left unused for hours) is closed too. Claude's background service may have stopped by then; stop starts it for a moment, and it goes away by itself. If Claude still cannot take the session out of its lists, stop says so and gives the command to do it later. A task with no session gets “nothing to close”, never a silent success.

  • --when-idle: wait until the session has finished its answer, then close it. Closing the task runs it by itself in the background: the session closing its own task is often still answering, and stopping it there would cut that answer off. A session can also close itself this way: the command returns at once, and a process in the background does the waiting. A session waiting for a permission counts as answering. It waits up to 30 minutes; one still answering by then stays open. What it did goes to state/session-stop.log in the configuration folder.

augmented-brain session restart

Restarts a Claude session so it uses the program of now, with the same conversation. It works from any folder. Use it after an update, or right after parking a task, so that its session starts afresh.

augmented-brain session restart task-new-website
augmented-brain session restart --old

The session is named by its task (when session start opened it), its id, the first eight characters of its session id, or its name; claude agents lists them. Each kind restarts its own way:

  • A task's session (claude --bg): Claude gives it a new process with the same conversation. One you archived, or that ended, is never brought back: only its augmented brain server stops, and it starts again, of now, if you ever open it.
  • A session of the remote access (remote install): its service restarts, and the same session comes back in claude.ai and Claude Desktop in about ten seconds. The service holds every session it serves, so it restarts only when all of them are idle. Anything else inside the service (Claude's background service, above all) is moved out first, so it does not stop with it. Linux only.
  • A session of Claude Desktop or a terminal: its window stays open. Its app opened it, and stopping it from outside would break that window, so only its augmented brain server stops; Claude Code starts it again, from the program of now, the next time the session uses it. Linux and macOS. On Windows it is left as it is: close it and open it again yourself.

A session that is answering, or waiting for a permission, is never restarted: it is looked at again right before, and left as it is if it is not idle. Nor is the session the command runs in: that one needs --when-idle. One that fails leaves the others going.

  • --old: restart every idle session still running an earlier augmented brain, one at a time, and say what happened to each. update runs it by itself. Here only a task's own session (opened by session start) is brought back: any other background session may have been archived in Claude Desktop, which Claude is not told, so only its augmented brain server stops.
  • --when-idle: wait until the session has finished its answer, then restart it. This is how a session restarts itself after parking its task: the command returns at once, and a process in the background waits, up to 30 minutes. What it did goes to state/session-restart.log in the configuration folder.

augmented-brain session list

Lists the task sessions open on this computer: the task, whether it runs, and its folder. retired means Claude stopped it, after hours unused or when its background service restarted: claude.ai shows it as disconnected, and session start with its task brings it back with its whole conversation. failed means its last answer was an error, such as an expired login: it does nothing until someone writes to it. The line gives the error and what to do.

augmented-brain watch

Follows something that takes a while and says how it ended, so a session can leave it running and get on with other work. For now it follows one thing, a pull request: see watch pr below. Without a subcommand, watch prints its usage.

augmented-brain watch pr

Follows a pull request on GitHub until there is something to tell: it is merged or closed, it conflicts with its base branch (no CI runs then), a required check fails, every required check has finished, or --max passes. Then it ends on its own and says how it went, in one line.

augmented-brain watch pr 104 --task task-my-change
  • --task TASK writes that line in the task's journal (with the next step the task had), and what happened, in a sentence of the program's own, as its next step: the names of the checks are chosen by whoever writes the pull request's workflows, so they go only in the journal, never in what every session reads at the start. Every other session hears of it before its next answer, and the panel's Today shows it. The watching is then done by a process of its own, which goes on if the session that started it is closed, restarted or retired by Claude: the session only waits for its result. Asked again for the same pull request and task, it waits for the one already running instead of starting another. The task must be in this folder's space.
  • --repo OWNER/NAME is the repository; by default, the one of this folder.
  • --max is the longest it watches (3h by default); --every how often it looks (30s by default, 10s at least).

The checks that are not required do not decide anything, but the line names those still running or failed: each name between quotes, on one line and cut at 60 characters, five at most. It never waits for ever: if GitHub lists no required check after 5 minutes, or gh fails three times in a row or gives an answer it does not understand, it stops and says what gh said. It needs gh with your GitHub login. The assistant runs it in the background; its last line asks it to tell you straight away. It ends with 0 when the checks passed or the pull request was merged, and 1 otherwise.

augmented-brain config

The versions of your configuration: two commands, history and restore, each with its own section below. Without a subcommand, config prints its usage. See Configuration versions.

augmented-brain config history

Lists the last versions of your configuration, newest first, and changes nothing.

augmented-brain config history
augmented-brain config history 3

A version is a copy of config.toml, guard.toml, remote.toml, session.toml, profile.md and secrets.toml as they were at one moment, with who changed them: the panel, a command, the assistant (and which tool), going back to a version, or by hand. The last 10 are kept, only on this computer. With a number, it shows what that version changed from the one before it, line by line. It takes no options.

augmented-brain config restore

Goes back to one version of the configuration.

augmented-brain config restore 3

It shows what changes and writes it. The configuration you had is kept as a version first, so going back can be undone the same way. A version that would leave a file the program cannot read is refused, and nothing changes. If the guard's lists end up different from the ones you accepted, the guard asks before every commit, push or merge it used to allow. It keeps asking until you accept the lists in the panel's Guard page, or start a new session. A command can be run by the assistant, so it never accepts them for you. Going back from the panel's Versions page does accept them. It works even when config.toml is broken, like config history. It takes no options.

augmented-brain clean

Removes what working with Claude Code leaves behind and nobody cleans up. It shows the list first, and removes it only if you say yes.

augmented-brain clean

It looks in every folder Claude Code was opened in, and in its scratch folder:

  • Worktrees Claude Code made (a worktree is a second working copy of a repository; Claude Code puts them in .claude/worktrees) whose session is over. One goes only when it has no change not committed, no commit that is not on the remote, and no file git ignores that no build makes again (a .env, a key): it is removed with git worktree remove, never by deleting the folder. Its branch goes with it when Claude Code named it (worktree-<name>); a branch of yours stays. A worktree with work of its own is only named, so you look at it.
  • Worktrees git remembers whose folder is gone: git worktree prune forgets them. Their branches stay.
  • Scratch folders of sessions that ended (/tmp/claude-<number> on Linux), untouched for over a day. Those of running sessions stay, and so does anything else there.

Before removing each thing it looks again, so a session that started meanwhile keeps its folders. doctor says when there is something to clean.

  • --yes: do not ask.

augmented-brain update

Updates augmented brain and its Claude Code plugin.

augmented-brain update

If there is a newer version, it runs the published installer, which replaces the program and then updates the plugin. If not, it only updates the plugin. It first asks GitHub for the latest version, once: if GitHub does not answer, it says so and stops. If the download of the installer fails (three tries, also through GitHub's API) or the program is not the new version afterwards, it says so, ends with an error and changes nothing. The installer tries the new program before it replaces the old one: if it does not start, the old one stays and update ends with an error. Around a new version it does what you would otherwise do by hand:

  • Before: the health check of doctor (what fails is shown, so it is not taken for a problem of the new version), and a backup of every space that has one. If a backup fails, it stops and updates nothing: that copy is the way back. With no backup at all, it says it goes ahead without a copy to go back to.
  • After: the idle Claude sessions still running the old version are restarted, one at a time, as session restart --old does: those of Claude Desktop stay open and only their augmented brain restarts. For those it cannot restart (one answering, or on Windows one of Claude Desktop), it says which task is active in each space, so you ask its session to park it, and then you close and open them.
  • --plugin: update only the Claude Code plugin. The installer uses it.
  • --force: update even when the backup before it fails.
  • --no-restart: restart no session after updating; it only says which still run the old version.
  • --from <address>: for tests: install the release at this address instead of GitHub's latest. It must be https://, file://, or http:// to this computer or to the host of a test VM (10.0.2.2).

update ignores AB_RELEASE_URL and AB_MARKETPLACE, and says so: a program could set them so that the update comes from somewhere else. Of the other AB_ variables, it only passes AB_CONFIG_DIR and AB_INSTALL_DIR on to the installer.

augmented-brain uninstall

Removes the program and the Claude Code plugin. Your notes stay.

augmented-brain uninstall

It shows what it will remove and asks first. The remote access services and the sessions opened for tasks go first; if one cannot be stopped, nothing else is removed.

  • --config: also remove the configuration and the profile.
  • --all: start from scratch: also the configuration, the profile and every space's notes. It shows each notes folder with how many notes it has, and warns about those with no backup, which will be gone for good. Only what augmented brain keeps in a notes folder goes; a folder that holds a work folder, or has no notes, stays whole. Your backups are not touched.
  • --yes: do not ask.

See Installing.

augmented-brain mcp

Runs the MCP server: the tools Claude uses to keep your tasks and notes. Claude Code starts it, through the plugin; you do not.

It talks over its input and output. It finds the space again on every call, from the folder Claude works in. The tools are in MCP tools. It takes no options.

augmented-brain hook

Answers a Claude Code hook: a call Claude Code makes at a given moment. Claude Code runs it, through the plugin; you do not. It reads what Claude Code sends on its input, and never makes Claude fail: a problem goes to its error output.

augmented-brain hook session-start 1

The events:

  • session-start: a session starts. It hands Claude the profile, the rules, the index of tasks and what is due. It comes in up to nine parts, session-start 1 to session-start 9, because Claude Code cuts each hook's text at 10,000 characters. Only the parts with something in them are sent.
  • pre-tool-use: before every command and file change. This is the guard. If it cannot run, Claude Code stops the command.
  • user-prompt-submit: before Claude answers a message. It tells Claude which tasks changed outside its session since it last looked (another session closed one, the panel changed its next step), so it reads them again instead of trusting what it read earlier. It never holds up the message.
  • stop: after each answer. It reminds Claude to write in the journal of its session's task, once, after 20 minutes without writing. It also looks at how much memory the window uses (VS Code's extension host, or Claude itself in a terminal), and has Claude warn you when it passes 2 GB, then 4 and 8 GB, once each. On Linux and macOS; it takes a fraction of a millisecond. See Troubleshooting.
  • post-compact: after Claude Code compacts a long conversation. It keeps the summary in archive/sessions/ and points the task's journal at it.
  • session-end: the session ends. It notes that it ended well, and starts the backup in the background.
