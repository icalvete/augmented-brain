A session per task

Each task can have a Claude session of its own, in its own folder. You ask for it in plain words, and it shows up in claude.ai and Claude Desktop within a minute, already reading its task. With several, you work on several tasks at once, from the computer or from your phone, and none of them steps on another.

Open a session for a task

Ask the session you are in: “open me a session for the website task”. Every session on Linux knows how, at the computer or from another one, because the start of each session tells it. It runs

augmented-brain session start task-new-website

and a new session, named after the task, shows up in claude.ai and Claude Desktop. It starts on its own: it reads its task, tells you in two or three lines where it stands, and gets on with the next step. It hears only what is its task's: that task's dates, not the rest of the space's reminders, the weekly review or sessions to recover, which come up in your other sessions. When it stops (the task closed or parked, or waiting on you), it tells the session that asked for it, in one line.

The command waits for the session's first answer, up to a minute. A session that cannot work is not left open: if Claude Code is not logged in, nothing opens, and if the first answer is an error (the login ran out, the service is overloaded), the session is closed. Either way the command says what to do, such as claude auth login.

Which folder it opens in

The folder is the first of the task's repositories found in the space's work folders. --folder gives another one, as long as it lies inside the space's work folders: a session elsewhere would not find its task. A task that names no repository opens in the space's first work folder.

augmented-brain session start task-new-website --folder ~/projects/website

Two rules keep it safe:

  • Claude must trust that folder itself. Trusting a folder above it is not enough: a repository's own settings and hooks must not run unasked. The first time, the command says what to do: on the computer (or through ssh), go to the folder, run claude, accept the question and close it with /exit. Then ask again.
  • One task per folder. Two tasks in one folder would step on each other's changes, so a folder another task's session uses is refused. Give it another one with --folder, such as a worktree (below).

Worktrees, for a bare repository

A worktree is a second working copy of a git repository: another folder, on another branch, sharing the same history. A bare repository is one with history but no working copy: some people keep each project that way and make a worktree for each piece of work.

When the task's repository is bare, session start makes the task a worktree of its own next to it: site-new-website for the task task-new-website of site, on a new branch named after the task, from the default branch of origin as it is now (it fetches first). So two tasks of one repository never share a folder, and a session never starts on old code. Asked again, it uses the same worktree. Claude keeps the trust of a worktree under its main repository: trusting either one is enough.

The worktree goes away by itself when nothing would be lost: with session stop, when the task is closed, or, for a session that ended some other way (a reboot, closing it from Claude Desktop), at the next session start. One with changes not committed, commits not pushed, or files git ignores that no build makes again (a .env, a key) stays, and augmented-brain doctor names it.

See them, and close them

augmented-brain session list

lists the task sessions open on this computer: the task, whether it runs, and its folder.

  • retired: Claude stops a session left unused for hours. claude.ai shows it as disconnected. session start with its task brings it back, with its whole conversation.
  • failed: its last answer was an error, such as an expired login. The line says what to do.
augmented-brain session stop task-new-website

closes the session and takes it out of Claude Desktop and claude.ai, worktree and all. Closing the task does the same, once the session has finished its answer. A session also ends when the computer restarts, and does not come back by itself: ask for it again.

Restart a session after an update

After augmented-brain update, open sessions still run the program they started with.

augmented-brain session restart task-new-website
augmented-brain session restart --old

The first restarts one session, with the same conversation; --old restarts every idle one still running an earlier version, and update runs it by itself. A session that is answering is never cut off. It works on Linux and macOS; on Windows, close the session and open it again yourself. Details in [session restart](commands.md#augmented-brain-session-restart).

Waiting on a pull request

A session that opened a pull request does not sit and wait for its checks. It leaves this running in the background, with its task:

augmented-brain watch pr 104 --task task-new-website

When the checks pass or fail, the pull request is merged or closed, or it conflicts with its base branch, it writes the result in the task, so your other sessions hear of it even if this one is gone, and the session tells you at once. It never waits for ever: 3 hours at most. It needs gh, GitHub's command, with your login. Every option is in [watch pr](commands.md#augmented-brain-watch-pr).

Clean up what is left

Claude Code makes worktrees and scratch folders of its own, and leaves some behind.

augmented-brain clean

shows what is left from sessions that are over, and removes it only if you say yes: never a worktree with work of its own, which it only names. doctor says when there is something to clean. Details in [clean](commands.md#augmented-brain-clean).
