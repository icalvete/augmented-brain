How it works

Four layers

LayerWhat it isWhere it lives
3 · You and your assistantYou talk to Claude Code as usual. No new commands to learn.Your terminal
2 · The pluginThe doors Claude uses to reach the program: two hooks and an MCP server.Inside Claude Code, which installs it
1 · The programaugmented-brain, a single file. It guards commands, keeps tasks, rebuilds the index and runs the backup.~/.local/bin/augmented-brain
0 · Your filesPlain text: the configuration, your notes and, if you want, their backup.~/.config/augmented-brain/, ~/augmented-brain/ and your git repo

Put another way: your notes are a notebook, the program keeps it in order and the plugin is the door. You only talk to Claude; Claude comes in through the door and the program writes in the notebook.

Two words that come up a lot:

  • Hook: a call Claude Code makes at a given moment. Here, when a session starts and before every command. Each time, Claude Code starts the program, asks it, and the program exits. Nothing keeps running in the background.
  • MCP (Model Context Protocol): an open standard to give tools to an assistant. The program offers its own (“open a task”, “park it”) and Claude uses them. Since it is a standard, other assistants will be able to use the same ones.

A session, step by step

1. You open Claude. The start hook looks at the folder you are in and picks your space. Before you type anything, it hands Claude your profile, your rules and the list of live tasks. That is how it knows where you left off.

2. You say “park it”. Claude uses the task_park tool. The program writes down in the task file where it stopped and what the next step is, and rebuilds the index. The next session starts from there. Opening, resuming and closing work the same way.

3. Claude is about to run a command. The guard hook reads it first and decides:

  • Go ahead: almost always. ls, go test, aws --profile dev s3 ls.
  • Ask you: production, or a machine you marked as untouchable. aws --profile prod …, ssh db01 ….
  • Stop: pushing code, root and secrets. git push, sudo …, a token in a command.

It also looks inside ssh, bash -c and loops. It is a net against slips, not a security wall: read the disclaimer.

Your files

Each space has its own notes folder:

~/augmented-brain/work/
├── MEMORY.md     the index Claude reads at the start (written by the program)
├── inbox.md      quick notes, to sort out later
├── areas/        what you always look after: "the website", "the servers"
├── tasks/        one file per task
├── knowledge/    how things work and what you learned
├── rules/        rules for this space only
├── reviews/      weekly reviews
└── archive/      old stuff; never loaded, never deleted

A task is a text file. At the top, between the --- lines, the data the program uses. Below, what you and Claude write:

---
id: task-add-a-contact-form
type: task
title: Add a contact form
area: area-website
status: parked
waiting_on: me
next: Write the plan
created: "2026-10-15"
updated: "2026-10-15"
---
## Essentials
Name, email and message, sent by email.

## Journal
- 2026-10-15 — Task opened.
- 2026-10-15 — Parked. Next: Write the plan

You can open and edit everything with any editor. The full format is in memory-format.md.

Work and personal, apart

A space is a full set of notes, rules and backup. The folder where you open Claude picks the space, following your configuration:

# ~/.config/augmented-brain/config.toml
[spaces.work]
memory = "~/augmented-brain/work"
work_folders = ["~/work"]

[spaces.personal]
memory = "~/augmented-brain/personal"
work_folders = ["~/personal"]

In ~/work/website, Claude sees your work notes. In ~/personal/blog, your personal ones. They never mix. To add another: augmented-brain space add.

The backup

Each space can have its own private git repository. augmented-brain backup pushes the changes; if another of your machines changed something, it merges that first. On a new machine, augmented-brain restore <url> brings everything back.

What it does not do

  • No server and no account. If Claude is not open, nothing runs.
  • It sends data to no one. Only the backup, if you set it up, talks to your repository.
  • It does not touch your Claude Code settings. The plugin goes in and out with Claude Code's own commands.
  • Mind this: your assistant reads your notes, like any file it opens. They travel with your conversations to its provider. Do not keep there what you would not share.

Remove it

claude plugin uninstall brain@augmented-brain
claude plugin marketplace remove augmented-brain
rm ~/.local/bin/augmented-brain
rm -r ~/.config/augmented-brain        # configuration and profile

Your notes stay in ~/augmented-brain/. They are yours.
